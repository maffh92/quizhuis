# 2026-05-22

## Research-phase full-capability contract

- `rpi.research` now treats every `FR-id` outcome as non-negotiable capability.
- Research guidance now forbids effort/complexity-based downscoping unless the request explicitly asks for phased delivery.
- Research must continue exploring alternatives until at least one implementation direction satisfies all `FR-id` outcomes.
- `research.md` now requires:
  - capability coverage contract (`FR-id` -> implementation direction -> verification intent)
  - rejected options mapped to unmet `FR-id` outcomes with rejection reasons
- `rpi.design-review` and `rpi.orchestrator` now fail/loop when research artifacts are missing that contract or reduce explicit requested capability.

## User approval checkpoint before planning

- RPI orchestration now includes an explicit user design-approval gate between `rpi.design-review` and `rpi.plan`.
- Even with a `PASS` design-review cycle, orchestration must pause and wait for an explicit user decision:
  - `approve-design` to proceed to planning
  - `request-design-changes` to rerun research/design-review with user feedback
- `rpi.plan` and `rpi-plan-agent` now require confirmation that user approval was received before planning can proceed.
- `rpi.design-review` and `rpi-design-review-agent` now require a user-approval packet in the latest design-review cycle to support this checkpoint.
