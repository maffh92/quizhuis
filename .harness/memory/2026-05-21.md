# 2026-05-21

## Workflow alignment: implement vs review gates

- `rpi.review` now requires independent verification of must-have acceptance criteria and primary flow behavior, not only `implementation.md` claims.
- `review.md` now requires a must-have verification table and regression notes; `PASS` is valid only with explicit independent evidence for all must-haves.
- `rpi.implement` now reads `review.md` on retry cycles, treats required fixes as in-scope, and must preserve previously passing must-have criteria.
- `rpi.orchestrator` now enforces verification-evidence completeness before advancing phases.
- Review artifacts are now append-only by cycle; orchestrator/implement/compound must read the latest appended review cycle as the active verdict/fix source.
- Design-review artifacts are now append-only by cycle; orchestrator/plan/implement must read the latest appended design-review cycle as the active planning gate verdict.

## Scope and consistency notes

- RPI agent profiles for implement/review were updated to match the stricter gate contract.
- Demo docs now reflect that design-review/review/compound behavior is skill-defined and that review is an independent correctness gate.
